AutorunEnum Updated sequential writer/critic workflow

Purpose:

Qwen and DeepSeek V4 Flash 0731 have different writer roles.
Qwen uses its 128K BF16 profile for broad analysis and the first SQL draft.
DeepSeek 0731 on antirez/ds4 uses the compact Hy3 feedback to produce the final SQL. The single-Spark profile uses SSD streaming and disables DSpark speculation to stay within memory.
Hy3 IQ1_M MTP remains an independent critic and reviews both candidates.
Only one large model is loaded on the DGX Spark at a time.

Default cycle (CRITIC_RETUNE_ROUNDS=1):

1. Qwen writes the initial candidate for every query.
2. Hy3 reviews every Qwen candidate and writes round-1 critique JSON.
3. DeepSeek 0731 reads the original SQL, Qwen candidate, analysis, DB context,
   and Hy3 feedback, then writes the final candidate.
4. Hy3 reviews every final DeepSeek candidate and writes round-2 critique JSON.
5. Oracle parse/explain/result validation and benchmark run when enabled.
6. All Llamacpp model containers stop for idle standby.

The final DeepSeek output is never treated as Hy3-approved merely because the
first Qwen candidate was approved. The second Hy3 pass is mandatory in the
default one-round flow.

Artifacts:

- workspace/B/rounds/round-1/<query>-B.sql: Qwen candidate
- workspace/critique/<query>/round-1/hy3.json: first Hy3 review
- workspace/B/rounds/round-2/<query>-B.sql: DeepSeek final candidate
- workspace/critique/<query>/round-2/hy3.json: final Hy3 review
- workspace/B/<query>-B.sql: latest candidate
- workspace/feedback/<query>.json: latest compact critic feedback
- workspace/validation/<query>.json: Oracle validation
- workspace/benchmark/<query>.json: benchmark result

Failure behavior:

- A Qwen failure preserves the original SQL for that query.
- A DeepSeek final-writer failure preserves the previous Qwen candidate.
- Invalid structured JSON is not accepted as SQL.
- A rejected final Hy3 review prevents critic approval.
- Oracle validation and benchmark remain the deterministic final gates.

Set CRITIC_RETUNE_ROUNDS=0 only when the DeepSeek final-writer stage should be
disabled. Additional rounds keep DeepSeek as the feedback writer and are meant
for explicit recovery experiments, not the normal default.
